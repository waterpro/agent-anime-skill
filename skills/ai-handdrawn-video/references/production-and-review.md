# 制作与验收细则

按正在处理的问题阅读对应小节。以下参数和文件名是示例，实际以简报和源素材为准。

## 角色与动作

| 检查对象 | 可观察的通过条件 |
| --- | --- |
| 角色身份 | 完整设定中的发型外轮廓、分缝、刘海、侧发、发丝、脸眼和衣装在目标画风下仍可辨认；睁眼、半闭眼、闭眼属于同一角色。 |
| 姿态锚点 | 头、颈、肩、肘、腕与身体朝向一致；同角色在相近镜头尺度下头肩比例稳定，远近景变化有构图依据。 |
| 抛接道具 | 按肩—肘—腕—手的参考动作重建；释放前球随手，释放后独立飞行，接触时手球相邻且遮挡合理，承重时姿态响应。 |
| 取景 | 审阅图保留足以判断头肩、半身与道具关系的范围；裁切遵循镜头构图，不用局部放大图掩盖比例问题。 |

例如角色 A 把球交给角色 B：先标出蓄力、释放、飞行、首次接触与接稳的关键姿态，再根据动作变化补帧。球移动而手一直停在低位，不构成抛球；对齐数值正确也不能替代这一视觉检查。

只替换头部时，复用已通过的躯干、手和道具。先查看不同头部角度、眼睛状态、手球越过脸部的极端姿态及镜头边界，再批量复用。替换区域以实际头部遮罩为准；固定高度线可能切入新头部，不能据此证明身体被改动或保持不变。

## 分层与局部修补

根据遮挡关系组织层：原片或清理底图 → 后景物体 → 人物与道具 → 前景物体与文字。物体穿过人物前后时，拆成必要的前后层，不要求所有镜头共用一个固定 z 序。

清理被替换角色的旧手、衣服和边缘，再检查新层外轮廓。文字使用可核实的文字层或局部遮罩；接近文字颜色的头发、衣装和背景应各自保留。单靠颜色阈值会误删这些区域。

局部贴片需要同时查看透明边缘和全画面效果：旧肢体露出、道具切片或缺失、矩形硬边、颈部断接均需修正。独立运动或跨越其他物体的兔耳、枕头等元素可拆为独立图层；仅在遮挡需要时拆分。

## 色彩、合成与资源

Python 可负责按时间取素材与分层合成，FFmpeg 负责媒体读取和编码。已有合成流程能解决问题时继续使用，不为单次修补重建整个工程。

先探测源文件的像素格式、色彩空间、传递特性、原色和范围。明确解码到 RGB、Python 处理、RGB 转 YUV 以及编码的每一步约定。raw RGB 字节自身不携带这些元数据，读写两端必须约定一致。

如果输入实际为 BT.709、有限范围 YUV，转换为全范围 RGB 后，编码时应执行对应的 RGB→BT.709 有限范围 YUV 转换，并使输出标签与转换一致。设置 `color_space` 等声明字段不能替代像素转换，也不能把未知素材随意标成 BT.709。对照源片与最终编码帧中的未修改区域，检查肤色、中性灰和背景是否整体漂移。

分辨率、帧率、音轨和编码参数由简报决定；例如无声、1080p、24 fps 只是一种交付。长片优先流式读写、有限缓存和适量线程。资源不足时减少自己的并发或批次，不关闭用户正在使用的应用。

## 验收证据与复用

1. 局部候选：查看本次标记的首、中、末帧，覆盖不同姿态、表情、接触/释放极值及相邻接缝。接触动作必要时逐帧查看相关小段。
2. 素材冻结：记录已通过素材的相对路径与内容哈希；生成新版本后撤销旧候选的当前引用，保留旧文件以便回退。重复姿态使用同版素材。
3. 实际成片：从最终 MP4 提取相同的代表帧，确认身份细节、遮挡、色彩与镜头衔接确实保留。必要时比较未修改区域像素，绑定成片与素材版本；压缩误差应与真实画面变动区分。
4. 技术检查：探测尺寸、帧率、时长、帧数和音轨是否符合约定，并完整解码检查错误。美术通过与技术通过分别记录。

最小记录可包含：`output/final.mp4` 的哈希、使用的素材版本、人工实际查看的代表帧、解码结果和未检查范围。不要复制未经复核的旧报告，把候选缓存通过写成成片通过，或把机器指标写成人工逐帧验收。
